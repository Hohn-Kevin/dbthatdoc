# Contributing to dbthatdoc

Thank you for your interest in contributing to dbthatdoc.

dbthatdoc is an open-source project focused on local document analysis and processing. This guide explains how to contribute in a way that keeps the project maintainable and useful for others.

## Project Principles

dbthatdoc follows these core principles:

- Local-first processing
- Privacy-focused design
- Transparent processing pipelines
- Modular architecture
- Open standards where practical

## Development Environment

The currently supported development environment is:

- Python 3.x
- Git
- Python virtual environments (`venv`)

## Contributing Changes

1. Fork the repository.
2. Create a dedicated branch.
3. Implement your changes.
4. Run the available tests.
5. Open a pull request.

Example branch name:

```bash
git checkout -b feature/new-functionality
```

## Pull Requests

A pull request should:

- Have a clear description of the change.
- Focus on a single topic.
- Avoid unrelated modifications.
- Include documentation updates where needed.
- Include or update tests when behavior changes.

## Issues

Please use GitHub Issues for:

- Bug reports
- Feature requests
- Architecture discussions
- Improvement proposals

When reporting a bug, include the document type, operating system, reproduction steps, and any relevant logs.

## Code Quality

New components should:

- Be documented clearly.
- Be independently testable where possible.
- Avoid requiring external cloud services.
- Follow the existing project structure.
